# 旧少量モデルの数量検証

検証日: 2026-10-24。対象は[施設・資源の提案](../../product-direction/factory-flow-proposal.md)。本製品用に選んだ試作用の値であり、参考ゲームの定数を移植したものではない。

この文書は改訂前の少量レシピを記録した旧案。現在の施設・ペンギン・遭遇確率の検討は[桁が増える生産と遭遇の検証](progression-review.md)を参照する。以下の値と現行レシピを混ぜて使わない。

計算結果はペンギン効果なしの基準。新しい[所持型の資源獲得効果](../../product-direction/penguin-effects-proposal.md)を含めた値ではない。

| ファイル | 内容 |

```text
python -X utf8 docs/domain/factory-economy/analyze_balance.py --optimize
```

## 計算条件

各生産施設は1棟ずつ配置済みで、すべて解放済み。稼働枠は600秒、開始在庫は0、補給は開始時にまとめて使えるものとする。G・E・Wはゲーム内の仮単位であり、歩数・実際の時間・飲水量への換算はしない。

連続量モデルでは端数バッチを許して理論上限を求める。整数モデルではバッチと納品個数を整数にする。どちらも品物の保存則、エネルギー予算、各施設の合計加工秒数を制約にする。

ただし、工程の開始・終了を時系列には配置しない。材料の到着を待つ時間、輸送、隣接と区画、保管上限、建築費、解放、初期支給、オフライン生産は含めていない。整数モデルも実際の10分間で達成できることを保証する値ではなく、集計制約の下での上限である。

## 次数・費用・比率

全レシピについて、出力次数が「最も高い材料次数＋1」になり、施設次数とも一致することを確認した。全レシピはR0を消費し、R0を生成するレシピや循環依存はない。

| 品物1個 | 次数 | 累積G | 累積E | 累積W | 納品点 | 点/合計エネルギー |
|---|---|---:|---:|---:|---:|---:|
| 魚 | R1 | 0.25 | 0 | 0 | 1 | 4 |
| 海藻 | R1 | 0 | 0 | 0.5 | 2 | 4 |
| 塩 | R1 | 0.25 | 0 | 0.25 | 2 | 4 |
| すり身 | R2 | 0.25 | 0.5 | 0 | 4 | 5.333 |
| 干物 | R2 | 0.875 | 0 | 0.125 | 6 | 6 |
| かまぼこ | R3 | 0.25 | 1 | 0.5 | 12 | 6.857 |
| ちくわ | R3 | 0.75 | 0.5 | 0 | 8 | 6.4 |
| 海鮮ギフト | R3 | 1.75 | 1 | 0.75 | 28 | 8 |
| 研究成果 | R3 | 0.5 | 3 | 0.5 | 32 | 8 |
| おでん | R4 | 2 | 1.5 | 2 | 44 | 8 |

累積費用は余剰在庫を増やさない長期平均。おでん・ギフト・研究を各4個ずつ独立に作る例は、前工程を含めて整数バッチで成立することも確認した。上位3経路について、点数あたりのG・E・Wすべてで他の経路より不利になるものはなかった。

3経路の点/合計エネルギーが8なのは、最初の比較基準として意図してそろえたため。この一致を面白さの証拠にはしない。エネルギーの実際の価値が異なれば重みを変えて再計算する。

## 補給の偏りによる結果

下表は連続量モデルの上限。端数は合計加工能力を表し、実際の納品に端数の品物を認める提案ではない。補給の合計量も異なるので、点数の差を難易度だけの差と解釈しない。

| 補給G/E/W | 最大納品点 | 有利だった構成の一例 |
|---|---:|---|
| 20 / 20 / 20 | 480.000 | おでん9.524・研究成果1.905 |
| 5 / 20 / 20 | 300.000 | 海藻30・研究成果6.190・おでん0.952 |
| 20 / 5 / 20 | 283.810 | 海藻22.857・干物15.238・おでん3.333 |
| 20 / 20 / 5 | 332.800 | ちくわ13.6・ギフト4.8・研究成果2.8 |
| 0 / 20 / 20 | 80.000 | 海藻40 |
| 20 / 0 / 20 | 205.714 | 海藻34.286・干物22.857 |
| 20 / 20 / 0 | 240.000 | すり身20・ちくわ20 |
| 0 / 0 / 0 | 0 | 生産・納品なし |

どの補給でも同じ品物だけを納品する解にはならなかった。G不足では研究、E不足では干物、W不足ではちくわ・ギフトが混ざる。特定の品物を常に要求する解放条件を課すと、この逃げ道が失われる可能性がある。

整数バッチでも8条件を計算し、保存則・エネルギー・加工能力を満たすことと、連続量の上限を超えないことを確認した。個数と点数は結果JSONの各条件の integer_batches に記録する。同じ最適点になる別の構成があるため、表示した内訳を唯一の正解とはしない。

整数バッチでの点数上限は、上表の順に472、286、276、326、80、204、240、0だった。連続量との差には端数の材料・加工バッチ・納品個数の影響がある。

## 物流を変えたときの予測

さばき場1棟の出力6個/分に対し、かまぼこ・ちくわ各1棟の最大入力は合計6個/分。さばき場からの配送能力が6未満なら、加工機の増設より配送が律速になる。倉庫の容量や速度の具体値は未決のため、物流が十分な場合の計算と分ける。

## 未検証の項目

- 初回の素材0から加工を始めたときの待ち時間と、解放を含む初回体験。
- 建築・移設・2×2の組み合わせ・再展開・納品の操作と理解。
- 倉庫の配分、輸送時間、満杯、生産停止中の中継、内部と上位の同時生産。
- 補給の実測分布、権限未許可や記録しない日の復帰経路。
- 品目の魅力、納品の達成感、日常行動を続ける動機。

次は時系列の試作で実際の在庫推移を測り、短い操作でも設計を改善できるかを確認する。今回の集計上限を、そのまま実機の生産目標や利用者の行動目標にはしない。
