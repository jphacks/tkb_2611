# 桁が増える生産・所持効果・遭遇確率の検証

検証日: 2026-10-24。現行の検討案は[施設](../../product-direction/factory-flow-proposal.md)と[ペンギン・遭遇](../../product-direction/penguin-effects-proposal.md)。旧少量モデルの balance-model.json・balance-results.json とは別の改訂モデル。

## 再現用ファイル

- [progression-model.json](progression-model.json): 100→1,000→10,000の材料、出力量、Lv倍率、19種の効果と重み。
- [analyze_progression.py](analyze_progression.py): 有理数での所持効果、空在庫からの時系列加工、確率DP、任意の線形計画。
- [progression-results.json](progression-results.json): 実行結果。通常抽選と新種保証、初回加工と集計上限を分けて保存。

```text
python -X utf8 docs/domain/factory-economy/analyze_progression.py
python -X utf8 docs/domain/factory-economy/analyze_progression.py --optimize
```

基本計算は標準ライブラリのみ。--optimizeだけSciPyを使う。

## 初回生産

各生産施設1棟を配置・解放済みとし、在庫0から最初のおでん1バッチを作る。必要なバッチ数を逆算し、材料がそろった工場から開始する。G/E/W各100を開始時に受け取る仮条件で、現実の日次の受取量を意味しない。ペンギンがいる場合はこの基礎補給にも所持効果を掛ける。

| 条件 | 完成までの秒 | おでん完成量 | 消費G/E/W |
|---|---:|---:|---|
| 全Lv1・ペンギンなし・R0無制限 | 40,100 | 100 | 2205 / 2200 / 205 |
| 全Lv4・ペンギンなし | 210 | 3,000 | 14 / 11 / 13 |
| 全Lv4・19種各1羽 | 180 | 7,200 | 12 / 8 / 11 |
| 全Lv4・19種各10羽 | 120 | 99,000 | 8 / 3 / 8 |

Lv1のケースはR0無制限という反実仮想。同じG/E/W各100では資源不足で停止した。Lv4の各ケースは仮補給内で完了した。19種各1羽・各10羽は効果を見る比較用で、遭遇確率から予測した所持数ではない。

余剰の品物は結果のleftoversへ残し、消えた扱いにしない。1バッチの完了を比較するため、出力量は条件ごとに異なる。この秒数を同じ個数を作る時間として比較してはならない。

開始・終了・材料待ちは計算するが、経路、配送、保管上限、組み合わせ境界、建築、解放までの進行、アプリ終了は含めない。特に全Lv4まで成長できる時期は未検証で、この結果を初回起動からの所要時間に読み替えない。

## 累積費用

次表はLv4・ペンギンなしで、余剰在庫を増やさない長期平均の1個分。整数バッチの初回消費と区別する。

| 品物 | 累積G | 累積E | 累積W | 点/R0合計 |
|---|---:|---:|---:|---:|
| 海鮮ギフト | 0.00011852 | 0.00066667 | 0.00011481 | 31,111.1 |
| 研究成果 | 0.00000370 | 0.00111111 | 0.00011111 | 26,102.7 |
| おでん | 0.00391358 | 0.00296296 | 0.00388889 | 27,867.0 |

同じ合計R0でも比率が異なり、電気・ガス・水のどれが不足するかで有利な経路が変わる。上位品の必要材料を増やしたまま旧納品点44を使うとおでんの評価が低くなるため、300へ変更した。補給やエネルギーの実際の価値が等しいという実証はない。

## 確率の確認

19種の重み合計は10,000。S1・S2・S3・S4の解放済み重み合計は6,000・8,600・9,900・10,000。各段階で未解放を除いて正規化し、合計1になることを有理数で確認した。

全解放後の通常抽選でマユダチ0.2%の場合、平均待ち回数は500、95%到達は1,497回。通常抽選だけなら1回目でも出る一方、有限回での保証はない。

新種保証は、20回新種なしの次の21回目に、解放済み未所持だけから抽選する。R4の2種だけ未所持という条件からのマユダチ獲得を、未所持集合と連続未発見回数を状態にしたDPで計算した。各回の状態確率と獲得済み確率の和が1であり、42回までの到達確率が1になることを確認した。平均35.495回、中央値42回、95%到達42回。保証があるため後半の特定回に確率が集中する。

報酬10回/日の上限は検知回数ではなく有効抽選回数。遭遇頻度を測っていないので回数を利用日数へ換算しない。新種保証は初獲得にだけ働き、同じ希少種を2羽目以降集める平均回数を500から35.5へ短縮する仕組みではない。

## 検証した不変条件と限界

全19種のIDが一意、全13資源に効能があること、次数の循環がないこと、全レシピがR0を消費すること、品物の生産−消費＝在庫、出現確率の正規化を確認した。ペンギンなしの倍率1、基礎量0からの獲得0、所持効果の計算例も確認した。

--optimizeの集計結果は、600秒・各施設1棟で、補給が均等、G不足、E不足、W不足、補給0の5条件を比較する。ペンギンなしと各種1羽を分け、材料の保存則・R0予算・総加工能力を守ることを確認する。この線形計画は端数バッチと工程順序の省略を含む上限であり、時系列の初回加工結果とは別物。補給0では両条件とも生産・納品0だった。

城の必要納品点、施設の底上げを開く条件、日常補給の分布、低遭遇頻度の獲得経路、Lv5とさらに先の進行、実機での楽しさは未検証。今回の計算だけで長期全体のバランスが完成したとはしない。
