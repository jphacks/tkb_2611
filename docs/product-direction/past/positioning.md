# 課題・対象者・独自性と発表の整理

更新日: 2026-10-24。発表の方針と、検証するための課題・対象者の候補をまとめる。実装済みの機能、利用者調査の結果、健康への効果を表す文書ではない。

2026-10-25 に、目的・課題・テーマを[生活習慣によって攻略が変わる工場ゲーム](../lifestyle-strategy-proposal.md)へ移した。この文書は現行の企画と矛盾する過去の案として残す。

## 発表の方針

課題解決をするプロダクトとして説明する。歩く・スマホから離れる・水分を補給する行動は、日常のセルフケアとして包括して扱う。工場やペンギンの育成は、その行動を続ける動機を支える仕組みとして位置づける。

独自性の中心は、自分の日常行動が工場のエネルギー源になり、得たエネルギーの使い道を自分で設計できることにある。ゲームの仕組みも、この特徴を説明するために用いる。

この発表方針は、既存のゲーム仕様や API 契約を変更するものではない。主課題・対象者の最終選定と、効果の検証は引き続き必要となる。

## 包括する課題の候補

以下は利用者調査で確かめるための仮説。運動不足・スマホ利用・飲水を個別の課題として並べる代わりに、複数の行動に共通する困りごとを置く。

| 候補 | 課題の仮説 | 対象者の仮説 | 製品で支援する方法 | 成立に必要な条件 |
|---|---|---|---|---|
| 1. セルフケアが続かない | 良い行動は分かっていても、成果がすぐに見えず後回しになる | 生活を整えようと習慣アプリなどを試したが続かなかった人 | 小さな行動を工場の成長に変え、続ける楽しみを作る | 成長への期待が、現実の行動を続ける動機になる |
| 2. 自分のケアを忘れる | 作業に没頭し、歩く・飲む・休むタイミングを逃す | 作業を始めると長時間座り続ける人 | セルフケアへ切り替えるきっかけを作る | 必要なタイミングで気づける。育成の報酬だけで解決できるとは置かない |
| 3. 習慣の管理が負担 | 歩数・飲水・スマホ時間を別々に記録・確認するのが面倒になる | 複数の記録アプリの入力や確認が続かない人 | 少ない操作で行動を反映し、一つの場所で振り返れるようにする | 自動取得の実現性と、工場操作を含めた負担の少なさを確認できる |
| 4. 小さな努力の成果を実感できない | 少しの行動では変化が見えず、取り組む意味を感じにくい | 数値やチェックマークだけでは達成感を得にくい人 | 行動の蓄積を、自分で育てる世界の成長として残す | 数字だけの場合より成果を実感でき、次の行動につながる |

現行の仕組みとの対応から、候補1を主課題、候補4を解決方法として組み合わせる案を推奨する。最終採用と対象者への適合は未確認。候補2には行動を思い出す仕組み、候補3には自動取得と操作の少なさが特に必要になる。

## 推奨案の課題とペルソナ

課題の表現案

> 生活を整えたいと思っていても、日常の小さなセルフケアは成果を実感しにくく、継続する動機を持ちにくい。

ペルソナは、実在の利用者ではなく行動・動機の仮説として定義する。

| 項目 | 仮説 |
|---|---|
| 日常 | スマホや PC に向かって座る時間が長い |
| 意向 | 歩く・スマホから離れる・水分を補給するなど、日常の行動から生活を整えたい |
| 過去の試み | 歩数や飲水などを記録したことはあるが、数字を確認するだけになって続かなかった |
| 求める価値 | 小さな行動にも成果があり、積み重ねを実感できる |
| 避けたい負担 | 毎日の手入力、厳しい目標管理、休んだ後の大きなペナルティ |

製品の説明案

> 日常のセルフケアで工場のエネルギーを作り、その使い道を自分で設計することで、行動の積み重ねを世界の成長として実感できるプロダクト。

## 着想の独自性

中心となる循環は次のとおり。

```text
日常の行動でエネルギーを得る
  → 使い道と工場の構成を自分で設計する
  → 工場が生産し、成長する
  → 次の日常行動に目的を持つ
```

利用者自身が生産システムの一部になることを、着想の特徴として説明する。ここでいうエネルギーはゲーム内の資源であり、現実の発電や環境負荷の削減を示すものではない。

歩行で苗を育てる [Pikmin Bloom](https://pikminbloom.com/gameplay) や、習慣・タスクをゲームの報酬につなげる [Habitica](https://habitica.com/static/features) に対し、本製品では複数の日常行動で得た異なるエネルギーを、自分で設計する工場の運転と成長へつなげる。比較した範囲での差別化仮説であり、同様の製品が存在しないとは断定しない。

2×2の建物を組み合わせ、ズームインで再編集できる機能は、エネルギーの使い道を設計する体験と、積み重ねによる成長を説明するために用いる。成立条件や生産方式などの未決事項は[製品方針](../README.md)を参照する。

## 参考採点

審査3項目・各5点を前提にした、文書上の企画に対する参考評価。公式の採点、受賞予測、実機検証の結果ではない。今年の公式審査ページの本文は未確認で、配点は関連資料の整理と[過年度の公式基準](https://jphacks.github.io/2021-guideline/criteria/)を参考にしている。

| 項目 | 仮の点数 | 根拠と限界 |
|---|---:|---|
| 問題着眼点・着想点 | 4 / 5 | 日常行動を異なるエネルギーにし、利用者自身を工場の生産システムに組み込むアプローチを評価する。世界初や効果の実証を意味しない |
| 実行・実現可能性 | 3 / 5程度 | セルフケアが続かなかった人という対象と利用理由を置ける。ただし対象者の適合と iOS 連携は未検証で、候補段階では2点寄りの可能性がある |
| 完成度・動作性 | 1 / 5相当 | 新方針の中心機能が動く証拠を docs から確認できない場合の評価。未実装と断定していない |
| 合計 | 8 / 15程度 | 着想4・実現可能性3・完成度1相当を置いた暫定値 |

着想を評価する際は、一般的な習慣化支援だけに要約せず、現実の行動・異なるエネルギー・自分で設計する生産網の関係を含める。課題の説明を変えるだけで、完成度の点数は上がらない。

## 90秒発表への反映案

| 時間 | 内容 |
|---|---|
| 0〜15秒 | セルフケアは成果が見えにくく、続けにくいという課題と対象者を示す |
| 15〜30秒 | 自分の日常行動が工場のエネルギー源になる仕組みを示す |
| 30〜65秒 | 行動の反映、エネルギーの利用、工場の生産・成長を示す。組み合わせと再編集も、実装済みなら実演する |
| 65〜80秒 | 行動の成果の使い道を自分で選べる特徴と、継続を支える仮説を説明する |
| 80〜90秒 | Hack Day 中に実装した差分と、実際に体験できる範囲を示す |

実演できない機能は構想として示す。ゲームのルールだけで時間を使わず、現実の行動がどう変わることを目指すかまでつなげる。

## 検証と未決事項

- 課題候補と主対象を最終選定し、実際に続かなかった場面と理由を聞く。時間不足や操作負担が主因なら、育成報酬だけでは解決できない可能性がある。
- 記録やポイントだけの場合と比べ、自分で使い道を設計することが次の行動の動機になるか確認する。
- アプリの滞在時間より、利用者が選んだセルフケアの継続、通常時からの行動変化、操作負担を評価する。比較方法と目標値は未決。
- エネルギー不足や工場管理が義務感にならないか、休んだ後も再開しやすいかを確かめる。
- スクリーンタイムの取得・配布条件などは[調査資料](../research.md)に従って確認する。睡眠・仕事・学習を含む非使用時間と、目的のないスマホ利用の削減を同じ指標として扱わない。
- 水エネルギーは現仕様ではスキャン時に付与する。スキャンは実際の飲水量の測定ではなく、飲水行動の変化を確認できたことにはならない。
- 実装と公開の差分は[Hack Day の規定](../../hackday.md)に従って示す。
