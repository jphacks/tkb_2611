# ペンギンの増量効果とすれ違い確率

更新日: 2026-10-24。配属なしで、所持しているだけで資源の獲得量を増やす方針を保つ。100→1,000→10,000と必要量が増える[施設案](factory-flow-proposal.md)に合わせ、旧案の一律5%・半減・直接1.21倍の上限を置き換える。数値と抽選・保証・報酬回数は検討案。

## 加算と乗算

```text
基礎生産量 = レシピの出力100 × 施設Lv倍率
獲得量 = 基礎獲得量 × (1 + 加算率合計) × (1 + 倍率枠の率合計)
```

R0では現実由来の基礎付与量、R1〜R4では上記の基礎生産量へ適用する。加算も倍率枠も、同種の羽数に比例して率が伸びる。例えば倍率枠+20%の個体が3羽なら×1.60であり、1.20の3乗にはしない。別の資源を得意とする種類の効果を、同じ資源へ掛けない。

| 対象次数 | 加算型1羽の増分 | 倍率型1羽の増分 |
|---|---:|---:|
| R0 | +10% | 倍率枠+5% |
| R1 | +20% | 倍率枠+10% |
| R2 | +30% | 今回は該当種なし |
| R3 | +50% | 倍率枠+15% |
| R4 | +100% | 倍率枠+20% |

アデリー3羽とジェンツー2羽なら魚は基礎量×1.60×1.20＝1.92倍。ヒガシイワトビ1羽とマユダチ1羽ならおでんは×2×1.20＝2.40倍。双方10羽ならおでんは×11×3＝33倍。これは所持状態を仮定した比較であり、10羽集める期間の予測ではない。

加算型も倍率型も個体ごとに率を足すため、同種を集め続ける意味がある。直接の固定上限は設けず、資源の要求量・施設Lv・加工能力・遭遇回数と合わせて成長させる。加算枠と倍率枠を掛けるので、両種が増えると対象資源の倍率は二次的に伸びる。将来の次数を追加する場合は、この伸びも再計算する。

## 段階による確率の変化

| 段階 | 開く種類 | 通常抽選の分母となる重み |
|---|---|---:|
| S1：R1の段階 | 基本6種 | 6,000 |
| S2：R2の段階 | S1＋R2の2種＋R0・魚の倍率4種 | 8,600 |
| S3：R3の段階 | S2＋R3の5種 | 9,900 |
| S4：R4の段階 | 全19種 | 10,000 |

通常確率＝その種類の重み÷解放済みの重み合計。S1のアデリーは1,400÷6,000＝約23.33%、S2のコウテイは200÷8,600＝約2.33%。全解放後の14%・2%と区別して表示する。各段階を開く納品点の閾値は未設定。

## 新種保証と報酬回数

通常抽選で20回連続、未所持の種類が出なかった場合、次の21回目は解放済み・未所持の種類だけから重みで抽選する。新種を獲得したらカウンタを0に戻す。未所持が残っていない場合は保証を止め、次の段階で候補が増えたら0から再開する。

保証カウンタは日をまたいで保持し、1日の報酬回数だけを日付で切り替える。1日10回の上限によって21回目の保証へ到達できなくなる設計にはしない。

保証抽選では上の通常確率を使わない。未所持集合の中で重みを正規化する。例えばR4の2種だけ未所持なら、保証抽選はヒガシ80%・マユダチ20%。ヒガシを先に獲得し、マユダチだけ残った次の保証抽選ではマユダチ100%。

同じ相手からの個体報酬はゲーム内1日1回、合計は1日10回までを仮置きする。対象外の再遭遇や回数上限後の挨拶は、抽選も保証カウンタも進めない。日付を切り替える基準と検知条件は未決。

## レア確率の読み方

保証なしで全解放後のマユダチだけを狙う場合、通常確率0.2%なので平均500回、95%の人が1羽以上得るには1,497回の抽選が必要。平均500回は500回で必ず出るという意味ではない。

他17種を所持済みで、R4の2種だけ未所持の状態からなら、上の保証によりマユダチ初獲得まで最大42回。厳密な確率計算では平均約35.50回、中央値と95%到達回数はいずれも42回。これはその所持状態からの条件付きの値。0羽から全種類を集める回数や、全利用者の所要日数ではない。

未解放は保証でも出さず、種類の解放だけで個体を付与しない。特定のレア個体を工場の建設・解放の必須条件にはしない。すれ違いがない環境の代替獲得経路や初期の相棒は引き続き未決。

## 適用の境目

R0は付与時、品物は生産完了時に1回だけ増量する。倉庫・中継・納品・再開で再適用しない。基礎量0は補正後も0。割合の加算なので受取回数の分割だけでは増えず、小数は資源ごとに繰り越す。

既存19種のID・和名と共通モデルを活かす。19種すべての専用3Dモデルの存在は未確認。今回の変更は設計と数量モデルのみ。ゲームコード・遭遇検知・セーブ・APIは変更していない。
