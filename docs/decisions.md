# 決定事項 (tkb_2611)

このリポジトリに関わる決定だけを書く。チーム全体の決定と JPHACKS の規定の正本は [project-penguin の `docs/decisions.md`](https://github.com/Sh1n1230/project-penguin/blob/main/docs/decisions.md)。

- **このリポジトリには backend と契約と README だけを置き、Unity クライアントは project-penguin に残して Web 版のリンクで渡す。** 差分評価で当日の成果がリポジトリの形のまま見え、LFS の移行や Unity の CI の移設が要らないため。 (2026-10-19、project-penguin #119)
- **Unity との契約の正本はこのリポジトリの `api/` とする。** 当日に契約を広げるのは backend の担当なので。project-penguin の `api/` は写しで、`check_api_contract.py --against` で一致を確かめる。 (2026-10-19)
- **このリポジトリは Vercel に繋がない。** 公開役が project-penguin の `deploy_web.py --backend ../tkb_2611/backend` で上げる。jphacks の org に外部アプリの承認を頼まずに済み、Web ビルドと同じ URL に置けるため。 (2026-10-19)
- **当日は Unity を作り直さない。** 変えてよいのは公開先の `penguin-config.json` だけ。そのために、検証の結果・みんなの氷山・お題まで、契約とクライアントの受け口を事前に作った。 (2026-10-19。CO₂e は 2026-10-22 に、量を出さないと決めて契約 1.1.0 から外した)
- **接続を足す・変えるときは、先に契約に書く。** 契約に無い通信はクライアントが受け取れず、当日まで食い違いに気付けないため。 (2026-10-19)
- **個人に関わる内容 (名前・連絡先・個人の事情・チームの会話の中身) をこのリポジトリに入れない。** org がある限りリポジトリは残り、push したものは消せないため。決まりだけでなく、Claude Code のフック・git のフック・CI で機械的に止める (`docs/personal-info.md`)。名前の拒否リストはリポジトリに入れず、手元のファイルと CI の Secret で渡す。 (2026-10-19)
- **LICENSE は運営の MIT のまま。** (2026-10-15、project-penguin の決定)
- **JPHACKS の後、製品の開発は project-penguin に戻し、`git subtree add` でこのリポジトリの backend を履歴ごと取り込む。** Web 版と Vercel のプロジェクトは審査が終わったら閉じる。 (2026-10-19)
- **写真判定の AI は Amazon Bedrock の Nova 2 Lite を、国内の推論プロファイル `jp.amazon.nova-2-lite-v1:0` で呼ぶ。** 申請なしで呼べ、試した 10 枚の分類がすべて正しく、1 枚 約 $0.0008 で、写真を国内のリージョンでだけ処理するため。`global.` のプロファイルは使わない。 (2026-10-22、project-penguin の ADR 0001、#125)
- **みんなの氷山の件数は DynamoDB に置き、提出の記録の条件付き Put が通ったときだけ、10 分割のカウンタに ADD する。** 再送を数えず、書き込みが集中してもぶつからないことを実測で確かめたため。トランザクションは同じカウンタでぶつかって数え落とすので使わない。 (2026-10-22、project-penguin の ADR 0002)
- **AWS の資源は CloudFormation (`infra/backend.yaml`) で作り、デプロイはオーナーだけが変更セットを確かめてから行う。** Vercel の関数は OIDC で IAM ロールを借り、長く使えるアクセスキーを作らない。 (2026-10-22、project-penguin の ADR 0003)
- **開発は GitHub flow で回し、main はルールセットで守る。** PR を必須にし、マージは squash だけにして履歴を一直線に保ち、CI の 5 つの検査を必須にする。管理者も例外にしない。org の都合で管理者が多く、例外を認めると直接 push を止められないため。squash したコミットは PR の題と説明を使い、「何を作ったか」が main の履歴に残るようにする。 (2026-10-23)
- **承認の数は 0 にし、マージ前にブランチを最新にすることも必須にしない。** Hack Day 中にレビューする人が空かずにマージが止まったり、PR が並んで更新待ちが連鎖したりするのを避けるため。組み合わせで壊れたら、main への push で回る CI で気付く。 (2026-10-23)
- **開始タグ `hackday-start` はルールセットで消せず付け直せないようにする。** 評価の基準点が後から動かないようにするため。 (2026-10-23)
- **シークレットスキャンと push protection を有効にする。** public のリポジトリなので費用がかからず、キーを含む push を GitHub 側でも止められるため。 (2026-10-23)
