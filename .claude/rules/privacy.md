# データ取り扱いルール

扱うのは**ユーザーが撮った写真**。部屋の中・顔・手書きの文字・位置が写りうる。以下は実装後に足す対策ではなく、書き始める前の制約として扱う。

## 写真

- **ディスクに書かない。** メモリ上で AI に渡し、応答を返したら捨てる。一時ファイル・アップロードディレクトリ・キャッシュを作らない。`UploadFile` は `await file.read()` でメモリに読み、`tempfile` や `SpooledTemporaryFile` のディスク退避に頼らない (上限 4 MB を先に確かめる)。
- **ログに出さない。** 画像のバイト列、AI の生の出力 (写真の説明文)、EXIF をログ・例外の文・トレースに入れない。記録してよいのは、例外の型・経路・状態コード・所要時間・トークン数だけ。
- **応答に入れない。** 応答は契約 (`api/openapi.yaml`) の項目だけ。AI の生の説明文や画像を返さない。エラーの応答にも入力の中身を入れない。
- **AI にはインラインで送る。** Files API・context caching・検索のグラウンディングなど、提供元に写真が別に残る機能を使わない (project-penguin #125)。

## 端末とユーザー

- 端末やユーザーを特定できる値 (端末の ID・IP の保存・広告 ID) を受け取らない・残さない。みんなの氷山の上限などで数が要るときは、サーバーのメモリの中だけで数え、保存しない。
- みんなの氷山の集計に外部の保存先 (Upstash など) を使うときも、保存するのは件数と節目だけにする。誰が送ったかは残さない。

## API キー

- 環境変数からのみ読む (`Settings`、名前は `PENGUIN_` で始める)。コード・設定ファイル・テストのフィクスチャ・`.env.example` に実値を書かない。
- **Unity クライアントに一切渡さない。** ビルドを展開すれば取り出せるため。

## テストデータ

- **実在の人や部屋が写った写真をリポジトリに置かない。** テストは合成画像か、AI をモックにして画像を使わない形にする。評価用の写真セット (project-penguin #89) はリポジトリの外に置く。

## 認証

エンドポイントの認証は無い (Hack Day の範囲)。クライアントに固定のシークレットを埋めるのは対策にならないので、そういう「API キーのヘッダー」を実装しない。乱用はレート制限 (`rate_limited`) と AI 側の上限額で抑える。
